# To Writing Studio 写作工作台 · Beta V3.8.0

> **English** · An AI-powered novel-writing workbench that helps people who have never used AI write a whole book with it.
> Purely static — no Node, no server, no build step. Open `index.html` (or the [live demo](https://theshyocean.github.io/to-writing-studio/)) and start writing.
> Bring your own API key (e.g. DeepSeek); it stays in your browser's localStorage and is never uploaded.
>
> **Features:** projects → volumes → chapters · AI chat per chapter with "adopt into chapter" · character / world-setting library · relationship & plot graphs · foreshadowing and timeline tracking · consistency checks · version history · export to .docx / .txt · daily word goals.
>
> This is my first project — feedback, issues and pull requests are very welcome! The UI is currently in Chinese.

**纯静态版本** —— 不需要 Node、不需要服务器。双击 `index.html` 就能用。

> 与 `beta2.0.04` 的区别：移除账号系统与协作室（入口保留，点击提示"暂未上线"），
> 新增八项写作功能。数据全部存在浏览器本地（localStorage）。

## 版本

> 目前所有版本都是 **Beta（测试版）**，还没有正式发版；以前标过的 V / Preview 版本号也一律算作 Beta。
>
> **版本号规则**（以 V3.4.6 为例，改动时请照此标注）：
> - **3 · 最大版本号**：只有项目发生翻天覆地的变化时才动（如整体重做、架构推倒重来）；
> - **4 · 大版本号**：只有上线了很多新功能时才升；
> - **6 · 小版本号**：优化、调整、修复（如换字体、改动画、修 Bug）都只升这一位。
>
> 升前面的号时，后面的号归零（如 V3.4.6 → V3.5.0）。

**Beta V3.8.0 · 2026-11-14**（电脑版 + 手机版）：补上写作与修稿的几个常用环节，沿用现有纸墨界面。
① **AI 修订对照**：选文润色、扩写、缩写、换个说法后高亮原文与改稿，可逐处采纳或保留原文，再应用选择。写回前保留历史；作品、章节或正文已经变化时拒绝覆盖。
② **旁批与待改清单**：选中正文可记旁批，也可记整章待办；支持编辑、完成、重新打开和删除，按作品、章节和状态筛选。引用随正文改动重新定位；原文消失或有歧义时保留批注并提示，不猜位置。
③ **固定参考页**：把人物／设定卡、章节原文或情节提纲固定到页边，切换章节时继续参照；窄屏和手机版使用抽屉。旁批存入章节的 `annotations`，参考选择存入作品的 `deskReference`，均随现有全书备份保存，不新增 localStorage 键。
④ **问自己的书**（书稿 → 工具）：默认查到当前章，可主动改为全书。无 Key 时展示本地检索到的原文；有 Key 时仅把候选原文交给当前模型，回答附可跳回书稿的引用。引用会核对是否确实出自候选原文；检索结果不是全书事实的完整证明，无法保证回答和推断一定正确。
⑤ **图标与入场**：统一常用小操作和分类切换按钮，保留提示与无障碍名称；「操作」使用三点菜单。入戏保留彩色双面具和悬停摇摆，新增蓝金双面具叠合、纸幕揭开的入场；塔罗使用抽牌台原来的七张牌飞入，直接接洗牌与翻面。支持跳过及系统减少动态效果。
**范围与验证**：本版仍为静态应用；To Account 目前仅有连接界面，账号服务和云端书稿同步尚未发布。已验证本地数据、批注／引用定位、修订选择、电脑和手机界面，以及过场／跳过／选牌流程；AI 流程使用受控测试响应验证，未使用真实付费模型作端到端验收。

**Beta V3.7.4 · 2026-11-13**（电脑版 + 手机版）：修正文字发糊、颜色过重。
① **去掉假粗体**（主要原因）。霞鹜文楷只有 Regular（400）和 Medium（500）两档，样式里却有几十处写了 `font-weight:600 / 700`。浏览器找不到那么粗的字，就在 Medium 上再描一圈假粗体。实测同一行字的墨量：常规 6.4%、真 Medium 7.9%、600 / 700 是 12.2%（比真 Medium 多一半，接近常规的两倍），笔画挤在一起，远看连成一片。现在全站 `font-synthesis:style small-caps`（不合成粗体，斜体不变），加粗一律落在文楷自带的 Medium 上，600 / 700 的墨量回到 7.9%。V3.3.0 说的「加粗用文楷自带的 Medium，不再是浏览器假粗体」当时并没有生效，这次才是。
② **正文色放浅**：昼读的 `--fg` 由 `#221f1b`（纸面上对比度 15.7:1，接近纯黑）改为 `#37332d`（12:1，仍远高于无障碍 AAA 的 7:1）。次要文字、说明文字不变。夜读配色不变。
③ 对话回复、AI 输出和弹窗正文里的加粗用 Medium + 原来的深墨色（`--fg-strong`），字重只差一档，再靠墨色拉开。
排查时排除的：鼠标视差（入场动画把正文区的变形锁成了不动，倾斜并未生效）、文字阴影和描边（只用在温度胶囊的显影动画和隐藏的旧元素上）。改动文件：`studio.css`、`js/tws-fun.css`、`desktop.html` / `mobile.html`（版本号）、`sw.js`（缓存版本）。

**开关**：系统配置 →「剧情完成 Finis」，默认开启，需要 API Key；旁边「看看效果」可以预览动画。新增文件 `js/tws-finis.js`；改动 `js/tws-kit.css`（动画样式）、`js/tws-backup.js`（备份清单加 `tws_finis`）、`desktop.html` / `mobile.html`、`sw.js`。

## 关键设计

### 一章一对话

每章对应一个写作会话。AI 写出来的内容，要在对话里点 **「采纳到本章」** 才会进入正文 ——
不自动写入，避免闲聊和重试污染正文。

### 数据在 localStorage

键名 `tws_data_v1`：

```
projects[] → volumes[] → chapters[]   章节含 content 正文与 words 字数
cards[]      设定卡片（人物/地点/名词/关系）
threads[]    伏笔
events[]     时间线事件
versions{}   每章版本快照（每章最多 20 版）
stats{}      每日字数
goal         每日目标
```

**容量**：localStorage 上限约 5MB。版本快照存全文，接近上限时程序会自动清理最旧的
AI 快照（手动与定稿版本优先保留）。

### 字数口径

中文按字符、英文按单词，去掉空白。**只在保存正文时计算**，避免多端算法不一致。

## 改代码注意事项

### 视觉改动优先写在 CSS 层

`terminal-redesign.css` 和 `js/tws.css` 都在 HTML 内联样式之后加载，靠覆盖生效。
直接改 HTML 内联样式会被盖掉。

### 图标系统

`.ico[data-ico="xxx"]` 由 `terminal-redesign.js` 注入 SVG，颜色由 `--c` 驱动
（双色瓷片：同色相淡底 + 描边 + 本色字形）。调色板 `--i1` ~ `--i9`。

注意 `data-ico` 打在 **`.ico` 自身**，不是父级 `.row`。

### API Key

对话与一致性检查需要用户自己的 API Key，存在 localStorage（`liangye_endfield_v2`
里的 `apiKey`），**不会上传到任何地方**。

未配置 Key 时：项目、正文、设定库、伏笔、导出全部可用；AI 续写与语义检查降级。

### 验证界面

系统 Edge 在浏览器开着时会把无头命令**转发到已有会话**，截图会静默失败。用 Playwright 绕过：

```js
chromium.launch({ channel: 'msedge' })   // 独立调试端口，不会被转发
```

## 已知限制

- To Account 需要另行运行兼容服务；本版不包含可部署的账号后端或云端书稿同步
- 问书采用关键词候选检索，可能漏掉相关片段；逐字引用校验不能保证模型的推断正确
- 协作室入口保留但未实现（点击提示"暂未上线敬请期待"）
- 正文用 `textarea`，不支持富文本
- 一致性检查的语义部分需要 API Key；无 Key 时只跑本地规则（名字、章节顺序）
- 数据不会自动跨设备同步（纯本地）；换设备靠「全书备份」手动搬
- 移动端技能标签条的右缘渐隐未实现
